
# AURA COFFEE — Maintenance Policy

## 1. Daily operations

- Review availability alerts.
- Review critical security alerts.
- Review failed automation executions.
- Verify backup completion status.

## 2. Weekly operations

- Review application errors.
- Review failed booking processing.
- Review database resource usage.
- Review security events.
- Verify critical automation workflows.

## 3. Monthly operations

- Review dependency vulnerabilities.
- Apply tested dependency updates.
- Review hosting and service expenses.
- Review database growth.
- Review access permissions.
- Perform an isolated recovery test.
- Prepare a maintenance report.

## 4. Incident priorities

P1 — Critical:

- Application unavailable.
- Data loss.
- Confirmed security breach.

P2 — High:

- Booking processing failure.
- Critical automation failure.

P3 — Medium:

- Partial functionality failure.
- Non-critical integration issues.

P4 — Low:

- Cosmetic defects.
- Minor improvements.

## 5. Incident handling

1. Detect the incident.
2. Determine business impact.
3. Record the incident.
4. Notify the responsible owner.
5. Mitigate the issue.
6. Restore normal operation.
7. Verify recovery.
8. Document the root cause.

## 6. Maintenance scope

Included services must be agreed with the client.

Potential services:

- Technical monitoring
- Bug fixes
- Security updates
- Backup verification
- Automation maintenance
- Monthly reporting

## 7. Exclusions

Unless separately agreed:

- New feature development
- Major redesigns
- Third-party subscription fees
- Third-party service outages
- Continuous 24/7 human support

## 8. Service level agreement

Support hours, response targets and availability
commitments must be agreed in a separate contract.

No contractual SLA is established by this document.
